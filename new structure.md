# Project Ownership and Team Structure

All participant accounts use the `STUDENT` role. Project-leader permissions belong to the user who created a specific project, not to a separate account role.

## Student and project workflow

- A student chooses whether to create a project or request to join an existing project.
- Creating a project makes that student the project leader and generates a stable project ID.
- Joining requires the project's stable project ID.
- The project leader approves or rejects membership requests.
- Only the project leader can submit project links or reports.
- A student may belong to only one ongoing project at a time.
- After a project is approved by the mentor, its accepted students may join or create another ongoing project.
- The project creator does not retain leader permissions outside that project.
- A member of one project can later create another project and become that project's leader.

## Mentor workflow

- Mentor accounts are created and provisioned by an administrator.
- Students can indicate a preferred mentor when creating a project.
- Administrators assign and change mentors for projects.
- An assigned mentor reviews submissions, manages milestones/tasks, and schedules reviews.

## Administrator workflow

- Administrators see students, mentors, projects, and unassigned projects.
- Administrators create mentor accounts and assign mentors to projects.
